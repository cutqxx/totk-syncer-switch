# totk-syncer-switch

Синхронизация сохранения The Legend of Zelda: Tears of the Kingdom между Nintendo Switch и ПК-портом totk-pc-recomp **напрямую по локальной сети**, без облака. На ПК работает лаунчер (`pc/`, C#/WPF) со встроенным HTTP-сервером, на Switch — утилита `totk-sync.nro` (`switch/`). Подробности — в `docs/specs/totk-sync-lan-spec.md`.

Сейчас реализованы Фаза 1 (лаунчер и отправка сейва Switch → ПК) и Фаза 2 (бэкап сейва Switch на SD и «Get from PC»: сейв ПК → Switch). Фаза 2 написана до проверки Фазы 1 на железе: проверяйте по порядку, сначала чек-лист Фазы 1, затем Фазы 2 (в конце файла).

## Установка тулчейна (Windows)

1. Установите [MSYS2](https://www.msys2.org/) в `C:\msys64`.
2. Подключите pacman-репозитории devkitPro в MSYS2 и установите пакеты:

   ```
   pacman -S switch-dev switch-curl switch-zlib
   ```

   (инструкция devkitPro: https://devkitpro.org/wiki/devkitPro_pacman). Тулчейн должен лежать в `/opt/devkitpro`.
3. Для хостовых тестов нужен gcc из MSYS2 UCRT64: `pacman -S mingw-w64-ucrt-x86_64-gcc make`.

## Сборка

Приложение для Switch лежит в каталоге `switch/` (`Makefile`, `source/`, `tests/`, `third_party/`). `build.ps1` остаётся в корне репозитория.

Путь проекта может содержать пробелы и кириллицу, а Makefile devkitPro этого не переносит. Поэтому используйте `build.ps1` из корня репозитория: он монтирует корень на свободную букву диска (T..Z) через `subst`, запускает make в `switch/` и снимает подстановку.

```
pwsh -File build.ps1 nro         # собрать switch/totk-sync.nro
pwsh -File build.ps1 test        # хостовые тесты (gcc UCRT64, без devkitPro и сети)
pwsh -File build.ps1 clean
pwsh -File build.ps1 pc-test     # тесты PC-лаунчера (dotnet test pc/TotkSync.slnx)
pwsh -File build.ps1 pc-publish  # публикация PC-лаунчера (профиль win-x64)
pwsh -File build.ps1 test-all    # test + pc-test
```

Готовый файл: `switch/totk-sync.nro`. Цели `pc-*` ищут `dotnet` в PATH, иначе в `C:\Program Files\dotnet\dotnet.exe`.

Из оболочки MSYS2 в каталоге без пробелов работают напрямую `make` (после `source /etc/profile.d/devkit-env.sh`) и `make test` в каталоге `switch/`.

Автоопределение конфига NPDM (`*.json` рядом с Makefile) в `switch/Makefile` отключено, так что случайный `config.json` или `switch-config.json` в `switch/` не превратит сборку в NSP. Всё равно держите свой конфиг на SD-карте, а не в репозитории.

## Лаунчер на ПК

Лаунчер (`TotkSync.exe`) показывает сейв ПК, принимает сейв со Switch и запускает игру кнопкой `Play`.

**Где взять `.exe`.** Готовых релизов пока нет, `.exe` собирается из исходников: `pwsh -File build.ps1 pc-publish`. Результат — один файл `pc/artifacts/publish/TotkSync.exe` (самодостаточный, ставить .NET не нужно). Положите его в любую папку и запускайте двойным щелчком.

**Первый запуск.**
1. Нажмите `Choose folder...` и выберите папку с `totk.exe`. Если `totk.exe` в ней нет, лаунчер покажет ошибку и ничего не сохранит.
2. Лаунчер сам найдёт папку сейва. Если сейва ещё нет, один раз запустите игру кнопкой `Play`: игра создаст его. Если папок несколько, выберите нужную кнопкой `Use this folder`.
3. Сервер стартует вместе с окном, токен создаётся автоматически. Настройки и журнал лежат в `%LOCALAPPDATA%\TotkSync`.

**Брандмауэр.** При первом запуске Windows спросит про доступ к сети: разрешите для частных сетей. Если нажали `Отмена`, откройте `Firewall help` в карточке `Server`: там есть команда для порта и подсказка про «Разрешение взаимодействия с приложением». Сеть ПК должна быть «Частной».

**Конфиг для Switch.** Нажмите `Save switch-config.json...`, сохраните файл и скопируйте его на SD-карту как `sd:/config/totk-sync/config.json` (подробности в разделе «Что положить на SD-карту»). Файл содержит токен: не публикуйте его.

**Порядок работы: отправить со Switch, потом Play на ПК.**
1. Закройте TotK на Switch и ПК. Лаунчер на ПК должен быть открыт.
2. На Switch запустите `totk-sync.nro` и отправьте сейв (`A - Send to PC`). Если на ПК есть прогресс, которого не было при последней синхронизации, Switch спросит подтверждение перед перезаписью. Перед заменой лаунчер делает бэкап.
3. На ПК нажмите `Play`. Пока игра запущена, кнопка неактивна (`TotK is running`), а лаунчер отклоняет запросы Switch.
4. После выхода из игры лаунчер снова принимает сейв. Если сейв ПК изменился после последней синхронизации, окно покажет `PC save has new progress: use "Get from PC" on Switch`.

Если сейв сейчас записывается, `Play` подождёт (`Waiting for save transfer to finish`) и запустит игру сам. Если закрыть окно во время записи, лаунчер дождётся её конца, остановит сервер и закроется, порт освободится для следующего запуска. Всё в главном окне доступно с клавиатуры (`Tab`, `Enter`, `Alt` + подчёркнутая буква).

## Что положить на SD-карту

| Файл | Куда |
| --- | --- |
| `switch/totk-sync.nro` | `sd:/switch/totk-sync/totk-sync.nro` |
| `switch-config.json` от лаунчера (переименовать в `config.json`) | `sd:/config/totk-sync/config.json` |

Конфиг не пишут вручную: в лаунчере на ПК нажмите `Save switch-config.json...`, сохраните файл и скопируйте его на SD под именем `config.json` в `sd:/config/totk-sync/` (лаунчер подсказывает этот путь). Образец формата: `contracts/switch-config.example.json`, правила проверки полей: `contracts/README.md`.

```
{ "pc_host": "192.168.1.10", "pc_port": 8765, "token": "<64 hex-символа от лаунчера>", "keep_backups": 20 }
```

- `pc_host` — частный IPv4 ПК (`10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`). `127.x.x.x`, публичные адреса и имена хостов отклоняются.
- `pc_port` — число от 1024 до 65535.
- `token` — секрет от лаунчера. Он не выводится на экран и не пишется в `log.txt`.
- `keep_backups` — необязательное целое от 1, по умолчанию 20 (понадобится для бэкапов на SD).

Реальный конфиг с токеном не храните в репозитории: `switch-config.json` и `config.json` уже в `.gitignore`.

### Сообщения о конфиге

| На экране | Что делать |
| --- | --- |
| `Config not found: ...` | положить файл по указанному пути |
| `Field "<имя>" missing or empty in <путь>` | в конфиге нет поля или оно пустое: заново сохранить `switch-config.json` из лаунчера |
| `Field "pc_host" must be a private IPv4 address ...` | в `pc_host` должен быть IPv4 из домашней сети |
| `Old Phase 0 config: save switch-config.json from the PC launcher` | на SD остался конфиг Яндекса из фазы 0: заменить его файлом из лаунчера |

Пока конфиг неверный, сетевых действий нет, доступен только выход по `+`.

## Использование

1. На ПК запустите лаунчер и оставьте его окно открытым: сервер работает, пока окно открыто.
2. Запустите `totk-sync.nro` из hbmenu. На экране: путь к конфигу, адрес `http://<pc_host>:<pc_port>`, строка статуса ПК и подсказки кнопок.
3. **R** — обновить статус, **+** — выход. Статус запрашивается при запуске и по R.
4. **A - Send to PC** — отправить сейв Switch на ПК (сейв Switch только читается).
5. **Y - Backup to SD** — сохранить сейв Switch на SD: `sd:/switch/totk-sync/backups/totk-<ГГГГММДД-ЧЧММСС>-manual.zip` (тот же ZIP, что уходит на ПК). Хранятся 20 последних (`keep_backups`), чужие файлы в папке не трогаются.
6. **X - Get from PC** — забрать сейв ПК и записать его в сейв Switch. Утилита скачивает сейв, проверяет ZIP и спрашивает `Restore to Switch? A - yes, B - no`. Если на Switch есть прогресс, который не уходил на ПК после последней синхронизации, над вопросом стоит `Switch save has progress not sent to PC!`: по A он пропадёт (останется только в бэкапе), так что сначала стоит отправить его на ПК. По A она делает и проверяет бэкап `...-before-pull.zip` на SD и только после этого пишет сейв. Пока идёт запись, HOME заблокирован. Если запись сломалась на середине, утилита предлагает вернуть этот бэкап (A) или оставить как есть (B). Если не удалось и возвращение, на экране путь к бэкапу: его можно восстановить через JKSV.

Строка статуса:

| Строка | Значение |
| --- | --- |
| `PC: online, save from <ГГГГ-ММ-ДД ЧЧ:ММ>` | лаунчер отвечает, сейв ПК найден (дата — время изменения сейва по часам ПК) |
| `PC: online, no save` | лаунчер отвечает, сейва ПК ещё нет: запустите TotK на ПК один раз |
| `PC: TotK is running` | на ПК запущена игра |
| `PC: not reachable` | ПК не отвечает (см. ниже) |
| `PC: error` | ответ получен, но он не годится; причина в строке ниже |

Сообщения об ошибках под строкой `PC: error`:

| Сообщение | Причина |
| --- | --- |
| `Wrong token: save switch-config.json from the PC launcher` | токен в конфиге не совпал с токеном лаунчера |
| `Not a TotK Sync launcher at <host>:<port>` | по этому адресу отвечает не лаунчер (другой сервис, неверный порт, несовместимая версия) |
| `PC refused this connection (HTTP 403)...` | лаунчер считает, что Switch не в частной сети |
| `PC error: HTTP <код>` | внутренняя ошибка лаунчера или неожиданный ответ |
| `Network error: curl <код>` | другой сбой соединения (например, обрыв: curl 56) |

### Если `PC: not reachable`

Соединение не удалось (curl 6, 7 или 28). Перед итоговой ошибкой утилита один раз повторяет запрос через 3 секунды. Проверьте по порядку:
1. Окно лаунчера открыто, карточка сервера показывает `Running`.
2. Switch и ПК в одной Wi-Fi/LAN-сети (не гостевая сеть, не изоляция клиентов в роутере).
3. Брандмауэр Windows пропускает входящие TCP на порт лаунчера в частной сети (кнопка `Firewall help` в лаунчере), сеть ПК помечена как «Частная».
4. Адрес `pc_host` в конфиге совпадает с адресом, выбранным в лаунчере. Если адрес ПК сменился (DHCP), сохраните конфиг заново.

**После смены порта в настройках лаунчера** сервер перезапускается на новом порту, а конфиг на SD остаётся со старым: нажмите `Save switch-config.json...` ещё раз и замените файл на SD. Пока этого не сделано, Switch покажет `PC: not reachable`.

Таймауты: соединение 5 с, весь запрос 60 с. Если лаунчер ответил HTTP-кодом (в том числе 401), повтора нет.

## Лог

Каждая попытка запроса дописывает запись в `sd:/switch/totk-sync/log.txt` (каталог создаётся при отсутствии): время, метод, номер попытки, HTTP-код, код и текст curl, время в секундах, URL и заголовки запроса и ответа. Тела запросов и ответов в лог не пишутся. Токен в лог не попадает: значение заголовка `Authorization` заменяется на `***`, и сама строка токена вырезается из всей записи. Если записать лог не удалось, один раз показывается `Log unavailable`.

Весь интерфейс и `log.txt` на английском: шрифт консоли libnx не содержит кириллицу и показывает её мусором.

Встроенная библиотека JSON: [cJSON](https://github.com/DaveGamble/cJSON), тег v1.7.18, лицензия MIT (`switch/third_party/cjson/`).

Встроенная библиотека ZIP: [miniz](https://github.com/richgel999/miniz) 3.0.2 (амальгама `miniz.c` + `miniz.h`), лицензия MIT (`switch/third_party/miniz/`). Собирается с `-DMINIZ_NO_ZLIB_COMPATIBLE_NAMES` (имена, как у zlib, конфликтуют с `-lz` из curl), `-DMINIZ_NO_STDIO` и `-DMINIZ_NO_ZLIB_APIS`.

## Безопасность канала

Запросы идут только по `http://` на частный IPv4 из конфига (в libcurl разрешён только протокол http, перенаправления отключены). TLS в этом протоколе нет: защиту дают токен, работа в частной сети и проверка адреса клиента на стороне лаунчера. Не пользуйтесь утилитой в недоверенных сетях (общественный Wi-Fi).

### Правило решения: основной путь / fallback §8

Если вариант по умолчанию даёт 2xx `SUCCESS` и размер файла на Диске совпадает с test.zip → основной путь (фазы 1-2). Если все варианты, включая .ru, chunked и длинный таймаут, стабильно дают curl 56 (как JKSV) → fallback §8. Если проходит только неосновной вариант → основной путь, этот вариант становится профилем по умолчанию в Фазе 1.

Решение (2026-11-03): **ни прямой Яндекс, ни rclone — синхронизация напрямую с ПК по локальной сети.**

Выводы прогона:
- Загрузка со Switch на Яндекс по WebDAV технически проходит: все загруженные файлы на Диске побайтно совпадают с исходными, в обоих режимах тела (Content-Length и chunked).
- Но ответ сервера идёт слишком долго или не приходит вовсе: для 1 МБ — 201 через 64,6 с, для 13 МБ — нет ответа даже за 600 с. Иногда соединение рвётся в начале передачи (curl 56), как у JKSV.
- DNS не причина: соединение и проверка TLS-сертификата проходят, тело уходит целиком.

Облако в схеме было только посредником, поэтому оно убрано. Новая схема: лаунчер на ПК запускает игру, работает с сохранениями и, пока открыт, отдаёт и принимает сейв по HTTP в локальной сети (свой простой API, доступ по токену, IP ПК в конфиге на Switch). Копия в Яндекс Диск не делается. Новый план описывается отдельным спеком.

## Чек-лист проверки на железе (слайс 1.4)

Отметьте после прогона на Switch с запущенным лаунчером.

- [ ] .nro запускается из hbmenu и показывает путь к конфигу, адрес `http://<pc_host>:<pc_port>`, строку статуса и подсказки `A - Send to PC`, `X - Get from PC`, `Y - Backup to SD`, `R - refresh`, `+ - exit`.
- [ ] Лаунчер открыт, сейв ПК есть: `PC: online, save from <дата время>`, время совпадает с датой сейва в карточке лаунчера.
- [ ] Сейва ПК нет: `PC: online, no save`.
- [ ] Игра на ПК запущена: `PC: TotK is running`.
- [ ] Лаунчер закрыт (или порт неверный): `PC: not reachable` и подсказка; через ~3 с утилита сама повторяет запрос один раз.
- [ ] Неверный токен в конфиге: `Wrong token: save switch-config.json from the PC launcher`.
- [ ] Токен не виден на экране и отсутствует в `sd:/switch/totk-sync/log.txt`; строка `Authorization` в логе заменена на `***`.
- [ ] R обновляет статус; `+` без зависания возвращает в hbmenu.
- [ ] Старый конфиг Яндекса на SD: `Old Phase 0 config: save switch-config.json from the PC launcher`.
- [ ] Конфиг с `pc_host` не из частной сети: ошибка про private IPv4, запросов в сеть нет.
- [ ] После смены порта в лаунчере и повторного сохранения `switch-config.json` статус снова `online`.

## Чек-лист проверки на железе (Фаза 2, остановка после Фазы 2)

Сначала пройдите чек-лист Фазы 1 выше: Фаза 2 пишет сейв Switch, и до неё на железе должны быть проверены чтение сейва, формат ZIP и сеть. Перед первым «Get from PC» сделайте страховочную копию сейва Switch через JKSV.

### Где смотреть

- Switch: `sd:/switch/totk-sync/log.txt`. По «Get from PC» пишутся строки `GET /save: ...` (размер и время скачивания), `Switch save: ... usable, journal ...` (размер сейва и журнала), `SD backup ...`, `Save write: ok|FAILED, <N> commits`.
- Switch: бэкапы в `sd:/switch/totk-sync/backups/`.
- ПК: журнал активности лаунчера (`Save sent to Switch`, `Sync confirmed by Switch`).

### Запись результатов

- Размер журнала сейва TotK и число commit'ов при записи (из `log.txt`): ______ байт, ______ commit'ов.
- Время скачивания и записи реального сейва: ______ с / ______ с.
- Режим запуска, в котором проверена запись (applet/album или title override): ______

### Слайс 2.1: выдача сейва лаунчером

### Слайс 2.2: бэкап на SD

- [ ] `Y - Backup to SD` создаёт бэкап и показывает `BACKUP OK: sd:/switch/totk-sync/backups/totk-<...>-manual.zip`.

### Слайс 2.3: «Get from PC»
