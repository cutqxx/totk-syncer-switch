# Spec: TotK Save Sync — синхронизация Switch ↔ ПК по локальной сети

> Статус: **подтверждён разработчиком 2026-11-03.** Решения — в разделе «Решения разработчика (2026-11-03)» в конце документа.
>
> Этот спек заменяет основной путь через Яндекс Диск (фазы 1–2 исходного ТЗ) и запасной вариант §8. Итоги фазы 0 и причина отказа от Яндекса описаны в `README.md`, раздел «Фаза 0 — результаты экспериментов».

## Обзор

Сохранение The Legend of Zelda: Tears of the Kingdom (title ID `0100F2C0115B6000`, сейв типа Account) переносится между Switch и ПК-портом totk-pc-recomp напрямую по локальной сети, без облака. На ПК работает нативный Windows-лаунчер: C# на .NET LTS, WPF и библиотека WPF-UI в стиле Fluent / Windows 11, один самодостаточный `.exe`. Лаунчер запускает `totk.exe`, хранит бэкапы и, пока открыт, по простому HTTP API с общим токеном принимает и отдаёт сейв. На Switch работает `totk-sync.nro` с действиями «Отправить на ПК» и «Забрать с ПК».

```
Switch (totk-sync.nro) ──HTTP по LAN + токен──▶ ПК-лаунчер (TotkSync.exe: WPF + встроенный HTTP-сервер)
  "Send to PC" / "Get from PC"                    ├─ отдаёт/принимает ZIP сейва, пока окно открыто
                                                  ├─ делает бэкап перед заменой
                                                  └─ запускает totk.exe (кнопка Play)
```

### Обозначения
- **[host]** — автотест на ПК. Для лаунчера это `dotnet test` (xUnit) над библиотекой доменной логики, без WPF. Для Switch это хостовые C-тесты `make test` (gcc UCRT64, без libnx и без сети). Сеть, файловая система сейва, проверка запущенной игры и часы подменяются фейками.
- **[HW]** — ручная проверка разработчиком на реальной Switch и/или ПК в одной сети, а также проверка интерфейса лаунчера глазами. Результат записывается в README.
- **[repo]** — проверяется просмотром репозитория или сборкой.

### Язык интерфейса
- Switch: экран и лог только на английском ASCII, потому что в шрифте консоли libnx нет кириллицы (решение фазы 0).
- ПК-лаунчер: интерфейс на английском.
- Спеки и README — на русском.
- Тексты в AC приведены так, как их увидит пользователь. Формулировку можно менять, но смысл и подставляемые значения должны остаться.

### Дизайн интерфейса лаунчера
У лаунчера настоящий GUI, поэтому **до начала кодирования Фазы 1** дизайн-агент готовит дизайн-бриф `.claude/DESIGN.md`. В нём: компоненты и токены WPF-UI (Fluent), раскладка главного окна, состояния, доступность. UI-критерии ниже описывают *что* видит пользователь, а бриф задаёт *как* это выглядит. Если бриф и AC расходятся по поведению, приоритет у AC.

## Инварианты безопасности (действуют во всех фазах)

Каждый инвариант проверяется конкретными AC в слайсах ниже.

1. Сейв на любой стороне не меняется, пока входящий ZIP не прошёл проверку по правилам раздела «Валидный ZIP сейва».
2. Сейв на любой стороне не меняется, пока перед этим не записан бэкап. На ПК бэкапы лежат в папке бэкапов лаунчера, на Switch — в `sd:/switch/totk-sync/backups/`.
3. Пока на своей стороне запущена игра, сейв не читается и не пишется. На ПК это процесс `totk.exe`. На Switch это TotK, запущенная или приостановленная; проверяется через `pmdmnt`.
4. Об успехе сообщается только после завершения последней записи. На Switch это commit сохранения.
5. Токен не выводится на экран Switch и не пишется ни в один лог. В лаунчере он скрыт, пока пользователь сам не нажмёт Show или Copy.
6. Лаунчер и утилита Switch удаляют только свои старые бэкапы и только по шаблону имени, который создали сами.
7. Мета-файл `.nx_save_meta.bin` никогда не создаётся и никогда не записывается в сейв.

## Разбиение на фазы

| Фаза | Что даёт пользователю | Что пишется | Остановка для HW-проверки |
|---|---|---|---|
| **Фаза 1** — лаунчер и отправка со Switch на ПК | Поиграл на Switch, нажал «Send to PC», играю на ПК с тем же прогрессом | Только сейв ПК, с бэкапом. Сейв Switch только читается | **СТОП** после Фазы 1 |
| **Фаза 2** — забрать сейв с ПК на Switch | Поиграл на ПК, нажал «Get from PC», продолжаю на Switch | Сейв Switch, с SD-бэкапом | **СТОП** после Фазы 2 |
| **Фаза 3** — полировка | Предупреждение о неотправленном прогрессе на Switch, восстановление из списка бэкапов, удобства | — | уточняется после Фазы 2 |

Порядок фаз выбран так, чтобы самая рискованная операция — запись сейва Switch (Фаза 2) — шла только после того, как на железе проверены чтение сейва Switch, формат ZIP и сетевой обмен (Фаза 1), а также SD-бэкап (Slice 2.2).

# Фаза 1 — ПК-лаунчер и отправка сейва со Switch на ПК

## Slice 1.1: Лаунчер — первый запуск и статус сейва ПК (без сети)

- [ ] [HW] При первом запуске без настроек окно предлагает выбрать папку игры (`game_dir`) через диалог выбора папки. Пока папка не выбрана, остальные функции недоступны.
- [x] [host] Папка игры принимается, только если в ней есть `totk.exe`. Иначе показывается `totk.exe not found in <path>`, и настройка не сохраняется.
- [x] [host] Папкой сейва ПК считается папка внутри `<game_dir>\profile\`, в которой есть `option.sav` и хотя бы один `slot_0N\progress.sav` (N = 0..5).
- [x] [host] Если подходящих папок несколько, статус сейва показывает их все и предлагает задать `save_dir` в настройках. Сам лаунчер ни одну не выбирает.
- [x] [host] Если папка сейва не найдена, статус сейва показывает `PC save not found: start TotK on PC once or set save folder in Settings`.
- [x] [host] Значение `save_dir` из настроек имеет приоритет над автопоиском.
- [ ] [HW] Карточка сейва ПК в главном окне показывает: путь к папке, дату последнего изменения, число файлов, суммарный размер, отпечаток (первые 12 символов), состояние синхронизации (`Last sync: <дата>, Switch -> PC` или `Never synced`).
- [x] [host] Мусорные файлы (`.nx_save_meta.bin`, `*.7z`, `*.zip`, `*.rar`, `desktop.ini`, `Thumbs.db`, без учёта регистра) не учитываются ни в числе файлов, ни в размере, ни в дате, ни в отпечатке.
- [x] [host] Страница настроек принимает порт только в диапазоне 1024–65535 и `keep_backups` только не меньше 1. При неверном значении показывается сообщение рядом с полем, и настройка не сохраняется.
- [x] [repo] В `pc/` лежат библиотека доменной логики без ссылок на WPF, WPF-приложение (WPF-UI) и проект xUnit-тестов. `dotnet test` запускает тесты. `dotnet publish` собирает один самодостаточный `.exe` для win-x64, которому на машине пользователя не нужен установленный .NET.

## Slice 1.2: Лаунчер — LAN-сервер и `GET /status`

- [x] [host] Сервер стартует при открытии окна на всех IPv4-интерфейсах на порту из настроек (по умолчанию 8765). Он работает, пока окно открыто.
- [ ] [HW] Карточка сервера показывает состояние (`Running` / `Error`) и адреса ПК в LAN в виде `http://192.168.x.y:8765`. Состояние передаётся текстом и значком, а не только цветом.
- [x] [host] `GET /status` с правильным токеном возвращает статус лаунчера и сейва ПК в формате из раздела «API».
- [x] [host] Запрос без токена или с неверным токеном отклоняется как неавторизованный, данных о сейве в ответе нет.
- [x] [host] Запрос с адреса не из частных диапазонов (10/8, 172.16/12, 192.168/16, 127/8) отклоняется как запрещённый.
- [x] [host] Неизвестный путь или метод получает ответ «не найдено» или «метод не поддерживается». Состояние сейва не меняется.
- [x] [host] Каждый запрос добавляет запись в журнал активности: время, IP клиента, метод, путь, результат. Токена в записи нет.
- [ ] [HW] Журнал активности в окне показывает записи запросов Switch, новые — сверху.
- [x] [host] Если порт занят, карточка сервера показывает `Error: port 8765 is busy (is the launcher already running?)`. Остальное окно (статус сейва, настройки, Play) продолжает работать.
- [ ] [HW] С другого устройства в той же сети (телефон или ноутбук) `GET /status` без токена получает отказ «неавторизован», а не таймаут. Значит, брандмауэр пропускает подключения.

## Slice 1.3: Лаунчер — сопряжение со Switch и помощь с брандмауэром

- [x] [host] При первом запуске генерируется случайный токен (не меньше 128 бит случайности) и сохраняется в настройках. При следующих запусках используется сохранённый токен.
- [ ] [HW] Токен в окне по умолчанию скрыт. Кнопки `Show` и `Copy` показывают его и копируют в буфер обмена.
- [ ] [HW] Кнопка `Save switch-config.json...` сохраняет файл через диалог и показывает, куда его положить на SD: `sd:/config/totk-sync/config.json`.
- [x] [host] В `switch-config.json` записываются LAN-адрес ПК (частный IPv4), порт из настроек, токен и `keep_backups: 20`. Если у ПК несколько частных адресов, используется адрес, выбранный в карточке сервера.
- [ ] [HW] При первом запуске и по кнопке `Firewall help` открывается панель с шагами: разрешить приложение в частных сетях, проверить, что профиль сети «Частная», и выполнить от администратора команду `netsh advfirewall firewall add rule ...`. У команды есть кнопка `Copy`.
- [x] [host] Текст команды для брандмауэра содержит порт из настроек, направление входящих подключений, протокол TCP и профиль `private`.

## Slice 1.4: Switch — подключение к ПК (сквозной ходячий скелет)

- [ ] [HW] Главный экран показывает путь к конфигу, адрес ПК `http://<pc_host>:<pc_port>`, строку статуса ПК и подсказки кнопок `A - Send to PC`, `R - refresh`, `+ - exit`.
- [ ] [HW] Строка статуса ПК — одна из: `PC: online, save from <YYYY-MM-DD HH:MM>`, `PC: online, no save`, `PC: TotK is running`, `PC: not reachable`, `PC: error` (ответ получен, но не годится; сообщение об ошибке — строкой ниже). Она обновляется при запуске и по кнопке R.
- [ ] [HW] Токен не отображается на экране ни в каком виде.
- [x] [host] Конфиг читается из `sd:/config/totk-sync/config.json`: поля `pc_host`, `pc_port`, `token` и необязательное `keep_backups` (по умолчанию 20).
- [x] [host] Если обязательного поля нет или оно пустое, показывается сообщение с именем поля и путём к файлу, а сетевые действия недоступны.
- [x] [host] Если `pc_host` не является IPv4-адресом из частных диапазонов (10/8, 172.16/12, 192.168/16; `127/8` для `pc_host` не допускается, это адрес самой Switch), показывается ошибка конфигурации. Запросы идут только по `http://` на `pc_host:pc_port`.
- [x] [host] Если в конфиге остались только поля Яндекса из фазы 0 (`origin`, `username`, `password`), показывается `Old Phase 0 config: save switch-config.json from the PC launcher`.
- [x] [host] Каждый запрос передаёт токен в заголовке `Authorization`. В `log.txt` значение этого заголовка заменено на `***`, и строка токена не встречается в логе нигде.
- [x] [host] Сообщения об ошибках:
  - неверный токен → `Wrong token: save switch-config.json from the PC launcher`;
  - curl 6/7/28 → `PC not reachable: is the launcher open? check firewall and same Wi-Fi`;
  - ответ без признака лаунчера → `Not a TotK Sync launcher at <host>:<port>`;
  - 403 от лаунчера (клиент не из частной сети) → `PC refused this connection (HTTP 403): Switch must be in the same private network`;
  - любой другой ответ → `PC error: HTTP <code>`.
- [x] [host] Таймаут соединения 5 с, общий таймаут 60 с. При curl 6/7/28/56 выполняется 1 повтор через 3 с.
- [x] [repo] Из приложения убраны: меню экспериментов фазы 0, загрузка `test.zip`, строки про Яндекс/WebDAV и запасной конфиг `sd:/config/JKSV/webdav.json`. Образец конфига `contracts/switch-config.example.json` (общий для ПК и Switch, отдельного `switch/config.example.json` нет) и README описывают новый формат.

## Slice 1.5: Лаунчер — приём сейва (`PUT /save`)

- [x] [host] Если ZIP валиден, токен верен и `totk.exe` не запущен, содержимое папки сейва ПК заменяется содержимым ZIP. Ответ — успех с именем созданного бэкапа.
- [x] [host] Перед заменой текущий сейв ПК упаковывается в `backups\pc-<YYYYMMDD-HHMMSS>-before-switch.zip`. Если бэкап записать не удалось, сейв не меняется и возвращается ошибка.
- [x] [host] После замены в папке сейва ровно те файлы и каталоги, что были в ZIP (кроме `.nx_save_meta.bin` и мусора), и они побайтно совпадают с содержимым ZIP. Пустые каталоги (например, `album/`) сохраняются.
- [x] [host] Мусорные файлы, которые уже были в папке сейва ПК, остаются нетронутыми. Файлы сейва, которых нет в ZIP, удаляются.
- [x] [host] При нарушении любого правила из раздела «Валидный ZIP сейва» приходит отказ с названием этого правила. Сейв ПК и папка бэкапов при этом не меняются.
- [x] [host] Если сейва ПК ещё нет, запрос отклоняется с `no PC save: start TotK on PC once`. На ПК ничего не создаётся.
- [x] [host] Запрос без `Content-Length` или с размером больше 64 МиБ отклоняется до чтения тела.
- [x] [host] Если запущен процесс `totk.exe` (не важно, кем запущен), запрос отклоняется с `game running`, и ничего не меняется.
- [x] [host] Если на любом шаге записи (распаковка, перемещение, переименование) возникает сбой, папка сейва ПК остаётся в прежнем состоянии побайтно, а временные файлы удаляются. Проверяется подстановкой сбоя на каждом шаге.
- [x] [host] Пока идёт одна запись, второй запрос на запись получает отказ `busy`. `GET /status` в это время видит либо старый, либо новый сейв, но не промежуточное состояние.

> **Известное ограничение.** При многократном сбое во время отката лаунчер может переименовать недопроверенный сейв в `<папка сейва>.totksync-bad-<id>`. Такое случается, если проверка установленного сейва не прошла, а убрать его не удалось ни переносом, ни удалением. Если в этой копии нет `option.sav` или `slot_0N/progress.sav`, сделать из неё проверенный бэкап нельзя. Тогда папка `-bad-` остаётся рядом с сейвом, и при каждом старте в `error.log` пишется заметка `Kept the unverified save … no verified backup`. На сейв ПК она не влияет: лаунчер её игнорирует, а прежний сейв восстановлен. Это неполная копия ZIP со Switch, и её оригинал остаётся на Switch. Папку можно удалить вручную.

## Slice 1.6: Switch — «Send to PC»

- [x] [HW] По кнопке A экран по шагам показывает проверку игры, чтение сейва, размер ZIP, отправку и результат `SENT TO PC. PC backup: <имя>`.
- [x] [host] Если TotK запущена или приостановлена, показывается `Close TotK first (HOME -> close the game)`. Сейв не монтируется, запрос не отправляется.
- [x] [host] Если сейв TotK есть только у одного аккаунта, он выбирается автоматически. Если таких аккаунтов несколько, показывается свой список аккаунтов для выбора. Если сейва нет ни у одного, показывается `No TotK save on this console`.
- [x] [host] Сейв монтируется только для чтения. За всю операцию в файловой системе сейва нет ни одной записи и ни одного commit (проверяется фейком ФС).
- [x] [host] Сейв размонтируется при любом исходе: успех, ошибка сети, отказ ПК.
- [x] [host] Все файлы сейва лежат в корне ZIP, вместе с записями каталогов, включая пустые. Их содержимое побайтно совпадает с сейвом. Мета-файла в архиве нет.
- [x] [host] Если сейв больше 64 МиБ, показывается ошибка с размером, и запрос не отправляется.
- [x] [host] Отказы ПК:
  - невалидный ZIP → `PC rejected the save: <причина>`;
  - на ПК запущена игра → `TotK is running on PC: close it and retry`;
  - ПК занят → `PC is busy: retry in a moment`;
  - на ПК нет сейва → `No save on PC yet: start TotK on PC once`.
- [x] [host] Дополнительные тексты (предложены слайсом, спек молчал):
  - `500 write_failed` → `PC error: <reason>` (в `reason` ПК всегда называет бэкап);
  - `401` с маркером → `Wrong token: ...`, ответ без маркера `X-TotkSync-Api: 1` → `Not a TotK Sync launcher at <host>:<port>`, остальные коды → `PC error: HTTP <code>` (как в Slice 1.4);
  - не удалось проверить, запущена ли TotK → `Cannot check whether TotK is running (error 0x<код>). Nothing was read` (обрабатывается как запущенная игра, сейв не монтируется);
  - сейв с более чем 1000 файлов и папок → `Save has more than 1000 files and folders. Nothing was sent`;
  - имя, которое ПК отверг бы (`\`, `:`, точка или пробел в конце сегмента, имена устройств Windows, не ASCII), → `Save has a name that cannot be sent safely: <имя>. Nothing was sent`; ничего не отправляется;
  - соединение оборвалось или истекло время после начала отправки тела → `Connection lost while sending (curl <код>). The PC may have received the save: check the launcher before retrying`.
- [x] [host] Отправка идёт с `Expect: 100-continue` (ожидание `100 Continue` 3 с). Если ПК отказал до чтения тела, а соединение затем оборвалось (curl 55/56 при HTTP-коде 400 и выше), Switch показывает отказ ПК, а не ошибку сети.
- [x] [host] Автоповтор PUT только при ошибке соединения до отправки тела (curl 6/7), один раз через 3 с. После таймаута или обрыва (curl 28/55/56) повтора нет: до Slice 1.7 каждый повтор делал бы на ПК новый бэкап и замену.
- [x] [host] Таймаут соединения 5 с. Общий таймаут PUT: 30 с плюс время передачи на скорости 64 КиБ/с, не больше 900 с (для сейва около 20 МБ около 350 с).
- [x] [host] В `log.txt` по каждой отправке пишется строка: размер ZIP, размер данных, файлы и папки, степень сжатия, отправлено байт, время, скорость, HTTP-код и код curl. Тела не пишутся.

## API

Каждый запрос передаёт `Authorization: Bearer <token>`. Нет токена или он неверный → `401`. Клиент не из частной сети → `403`. Ответы — JSON, кроме `GET /save`.

```
GET /status
→ 200 { "app": "totk-sync", "api": 1, "game_running": false,
        "save": { "present": true, "modified": "2026-11-03T14:25:01+03:00",
                  "files": 27, "bytes": 20123456, "fingerprint": "sha256:<hex>" },
        "last_sync": { "fingerprint": "sha256:<hex>", "at": "2026-11-03T12:00:00+03:00",
                       "direction": "switch->pc" } | null }

GET /save
→ 200 application/zip   X-TotkSync-Fingerprint: sha256:<hex>
                        X-TotkSync-Modified: 2026-11-03T14:25:01+03:00
→ 404 { "error": "no_save" }      → 423 { "error": "game_running" }

PUT /save[?force=1]     Content-Type: application/zip, Content-Length обязателен
→ 200 { "result": "replaced", "backup": "pc-20261103-142501-before-switch.zip", "fingerprint": "sha256:<hex>" }
→ 200 { "result": "unchanged", "fingerprint": "sha256:<hex>" }
→ 400 { "error": "invalid_zip", "reason": "missing option.sav" }
→ 404 { "error": "no_save" }
→ 409 { "error": "conflict", "pc_modified": "...", "last_sync_at": "..." | null }
→ 411 (нет Content-Length)   → 413 (> 64 МиБ)   → 423 { "error": "game_running" }
→ 503 { "error": "busy" }

POST /save/ack          { "fingerprint": "sha256:<hex>" }
→ 200 { "result": "recorded" }   → 409 { "error": "fingerprint_mismatch" }
```

## Форматы

```
Switch: sd:/config/totk-sync/config.json   (лаунчер сохраняет его как switch-config.json)
{ "pc_host": "192.168.1.10", "pc_port": 8765, "token": "<случайный>", "keep_backups": 20 }

ПК: %LOCALAPPDATA%\TotkSync\settings.json
{ "game_dir": "D:\\Games\\totk-pc-recomp", "save_dir": null, "port": 8765,
  "token": "<случайный>", "keep_backups": 20 }

ПК: %LOCALAPPDATA%\TotkSync\sync_state\state.json
{ "last_sync": { "fingerprint": "sha256:<hex>", "at": "<ISO 8601 с часовым поясом>",
                 "direction": "switch->pc" | "pc->switch" } }

Бэкапы ПК:     %LOCALAPPDATA%\TotkSync\backups\pc-<YYYYMMDD-HHMMSS>-before-switch.zip
Бэкапы Switch: sd:/switch/totk-sync/backups/totk-<YYYYMMDD-HHMMSS>-<manual|before-pull>.zip
```

Данные лаунчера хранятся в `%LOCALAPPDATA%\TotkSync\`, а не рядом с `.exe`. Так приложение работает из любой папки, включая папки без права записи, и в репозиторий ничего не попадает.

**Раскладка сейва.** На Switch и ПК она одинакова, проверено в обе стороны:
- `option.sav`;
- `slot_00..05/{caption,direct_file_save_related,footprint,progress}.sav`;
- `album/`, `picturebook/`;
- `storage/CacheStorageKey.dat`.

Общий размер около 20 МБ.

**Формат ZIP** (совместим с JKSV). Файлы сейва лежат в корне архива, есть записи каталогов, разделитель путей `/`. У JKSV в корне может быть `.nx_save_meta.bin` (86 байт, магия `JKSV`, версия 01, title ID в little-endian со смещения 0x05). Без него JKSV тоже восстанавливает сейв, только с предупреждением. Наша утилита и лаунчер этот файл не создают.

**Отпечаток сейва** (`sha256:<hex>`). Это SHA-256 от строк `<относительный путь с />\n<hex sha256 содержимого>\n` по всем файлам сейва, отсортированным по пути побайтно в UTF-8. Мусор, мета-файл и каталоги в отпечаток не входят. От сжатия ZIP и меток времени отпечаток не зависит. В Фазах 1–2 его считает только лаунчер, на Switch — с Фазы 3.

### Валидный ZIP сейва (общие правила для обеих сторон)
1. Файл открывается как ZIP, CRC всех записей сходятся.
2. Ни одна запись не начинается с `/` и не содержит букву диска, `\` или сегмент `..`.
3. Пути не повторяются.
4. В корне есть `option.sav` и хотя бы один `slot_0N/progress.sav` (N = 0..5).
5. Суммарный распакованный размер не больше 64 МиБ, записей не больше 1000.
6. Если в архиве есть `.nx_save_meta.bin`, у него должна быть магия `JKSV` и title ID `0100F2C0115B6000`. Иначе отказ `save of another game`. Сам мета-файл в сейв не записывается.
7. Мусорные записи (`.nx_save_meta.bin`, `*.7z`, `*.zip`, `*.rar`, `desktop.ini`, `Thumbs.db`) не делают ZIP невалидным, но в сейв никогда не записываются.

## Вне объёма

- Яндекс Диск и любое облако, WebDAV, rclone.
- TLS и шифрование трафика. Защиту дают токен, работа только в частной сети и проверка адреса клиента. Пользоваться в недоверенных сетях (например, в общественном Wi-Fi) не предполагается.
- Автоматическое обнаружение ПК в сети (mDNS, broadcast). Адрес ПК задаётся в конфиге.
- Работа лаунчера как фоновой службы, из трея или вместе с автозагрузкой Windows. Сервер работает, только пока окно открыто.
- Синхронизация, которую начинает ПК. У Switch нет сервера, поэтому обмен всегда начинает Switch.
- Автоматическое слияние сейвов. При конфликте выбирает пользователь.
- Создание `.nx_save_meta.bin` и увеличение размера сейва (как это делает JKSV).
- Несколько игр, несколько ПК, Linux/Steam Deck, версии ПК-порта, которые хранят сейв не в `profile\`.
- Добавление правила брандмауэра самим лаунчером. Он даёт только инструкцию и готовую команду.
- Отмена передачи посреди операции.
- Установщик (MSI/MSIX), автообновление, подпись `.exe`.
- Локализация лаунчера. Интерфейс только на английском.

## Технический контекст

- **Switch.** C, devkitPro + libnx, switch-curl (только http; TLS-бэкенд libnx не используется), switch-zlib, cJSON. Хостовые тесты: `make test` (gcc UCRT64). Сборка через `build.ps1`, который делает `subst`, потому что в пути есть пробел и кириллица.
- **ПК.**
  - C# на .NET LTS (на ноябрь 2026 — .NET 10), WPF, библиотека WPF-UI (NuGet `WPF-UI`, стиль Fluent). Публикуется как один самодостаточный `.exe` для win-x64.
  - Доменная логика живёт в отдельной библиотеке без ссылок на WPF и тестируется xUnit через `dotnet test`: поиск сейва, валидация ZIP, отпечаток, бэкап и ротация, замена зеркалом, конфликт и `state.json`, обработка HTTP-запросов, проверка запущенной игры через подменяемый интерфейс.
  - HTTP-сервер встраивается в то же приложение; конкретную технологию выбирает архитектура. У `HttpListener` есть особенность: префикс не на localhost (`http://+:8765/`) без прав администратора требует резервирования URL ACL (`netsh http add urlacl`). Kestrel работает с сокетами напрямую и такого резервирования не требует, но увеличивает размер `.exe`. Это нужно учесть при выборе.
  - Токен сравнивается за постоянное время (`CryptographicOperations.FixedTimeEquals`). Запущенный `totk.exe` ищется по имени процесса, потому что игру могут запустить и не через лаунчер.
- **Окружение.** На машине разработчика пока нет .NET SDK, только хост `dotnet`. SDK (LTS) нужно установить через winget до начала кодирования Фазы 1. Пользователю .NET не нужен, так как `.exe` самодостаточный.
- **Дизайн.** До кодирования Фазы 1 дизайн-агент готовит бриф интерфейса лаунчера `.claude/DESIGN.md` на основе WPF-UI и Fluent: раскладка окна, состояния карточек, доступность — контраст, клавиатура, статус не только цветом.
- **Сейв Switch.** Account save для `0100F2C0115B6000`, нужен UID выбранного аккаунта. Запись в сейв ограничена журналом. Если весь объём не помещается в журнал, commit делается после каждого файла, как в JKSV; как узнать размер журнала, решает архитектура. Если приложение запущено в applet-режиме (album), пока TotK приостановлена, игра считается запущенной. Системный выбор пользователя (`pselShowUserSelector`) в applet-режиме может не работать, поэтому список аккаунтов свой.
- **Память.** ZIP целиком держится в памяти (до 64 МиБ, сейв около 20 МБ). Это приемлемо и в applet-режиме, проверяется на железе в Slice 1.6.
- **Атомарность на ПК.** Распаковка идёт во временную папку рядом с папкой сейва, затем папки переименовываются. На Switch атомарность не гарантирована: её заменяют SD-бэкап и восстановление (Slice 2.4).
- **Брандмауэр Windows.** При первом прослушивании порта Windows может показать запрос для `TotkSync.exe`. Если сеть помечена как «Общедоступная», входящие подключения из LAN блокируются.
- **Уровень риска: HIGH.** Сейвы пишутся на обеих сторонах. Самая рискованная операция — запись сейва Switch — стоит в Фазе 2, после проверки путей чтения на железе.

## Решения разработчика (2026-11-03)

1. **API:** `GET /status`, `GET /save`, `PUT /save[?force=1]`, `POST /save/ack`. Тело передаётся как ZIP без изменений, токен — в `Authorization: Bearer`.
2. **Сопряжение:** лаунчер сам генерирует случайный токен и сохраняет готовый `switch-config.json` для SD. `pc_host` — только частный IPv4. Порт по умолчанию 8765.
3. **Конфликты:** лаунчер хранит отпечаток последней синхронизации. Если при отправке оказалось, что сейв ПК изменился с тех пор, Switch спрашивает A/B. По A запрос повторяется с `force`, сейв ПК сначала бэкапится.
4. **Бэкапы:** хранится по 20 на ПК и на SD. Удаляются только файлы по своему шаблону имени.
5. **Лаунчер** — нативный Windows-клиент: C# на .NET LTS, WPF, WPF-UI (Fluent / Windows 11), один самодостаточный `.exe`, интерфейс на английском. Python-лаунчер не делается. Один `.exe` содержит интерфейс, LAN-сервер, запуск игры и бэкапы. Сервер работает, пока окно открыто. Конкретную технологию HTTP-сервера выбирает архитектура. Тесты — xUnit через `dotnet test`, доменная логика — в библиотеке, которая не зависит от UI.
6. **`.nx_save_meta.bin`:** никогда не создаётся. Если он есть во входящем ZIP, проверяются магия и title ID. В сейв он не записывается никогда.
7. **Замена сейва ПК:** точное зеркало ZIP. Файлы сейва, которых нет в ZIP, удаляются, мусор не трогается. Если сейва ПК ещё нет, запрос отклоняется (`start TotK on PC once`).
8. **Интерфейс Switch:**
   - кнопки: A — Send to PC, X — Get from PC, Y — Backup to SD, R — обновить статус, + — выход;
   - аккаунт выбирается автоматически, если сейв TotK есть только у одного; иначе — свой список;
   - ZIP проверяется до вопроса «Restore? A/B»;
   - отдельный пункт «Backup to SD»;
   - таймауты 5 с / 60 с.
9. **Языки:** интерфейс Switch на английском ASCII (из-за шрифта консоли), интерфейс лаунчера на английском, спеки и README на русском.
10. **Дизайн-бриф** интерфейса лаунчера готовится до начала кодирования Фазы 1.
