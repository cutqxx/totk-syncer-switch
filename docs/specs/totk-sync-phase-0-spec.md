# Spec: TotK Save Sync — Фаза 0 (upload spike)

> Статус: **подтверждён разработчиком 2026-11-03.** Решения по открытым вопросам — в разделе «Решения разработчика».

## Обзор

Минимальная .nro-утилита для Switch (devkitPro + libnx). Она читает конфиг, загружает тестовый файл `sd:/switch/totk-sync/test.zip` на Яндекс Диск через WebDAV PUT по правилам §5.4 и показывает HTTP-код, код curl и время. Фаза нужна, чтобы на реальном железе проверить, работает ли загрузка там, где JKSV падает с curl 56. От результата зависит судьба проекта: продолжаем основной путь (фазы 1–2) или переходим на запасной вариант §8 (rclone serve webdav по LAN).

**После фазы 0 — СТОП.** Разработчик тестирует на железе. Фазы 1–2 начинаются только после результата.

### Обозначения
- **[host]** — проверяется автотестом на ПК (MSYS2 gcc, без Switch и без сети).
- **[HW]** — ручная проверка разработчиком на реальной Switch с сетью. Автотеста нет, результат фиксируется в README.
- **[repo]** — проверяется просмотром репозитория или сборкой.

- [ ] [HW] .nro запускается из hbmenu и показывает экран: origin, username, полный URL назначения и подсказки по кнопкам (A — загрузить, + — выход).
- [ ] [HW] Пароль не отображается на экране ни в каком виде.
- [ ] [HW] По нажатию A файл `sd:/switch/totk-sync/test.zip` загружается, и на экране появляется строка результата: HTTP-код, код curl (с текстом ошибки curl), время в секундах, сколько байт отправлено из скольких.
- [ ] [HW] **Критерий приёмки фазы:** при настройках по умолчанию сервер отвечает 201 или 204, а на экране написано «УСПЕХ».
- [ ] [HW] Загруженный файл виден в папке `JKSV/The Legend of Zelda Tears of the Kingdom/` на Яндекс Диске и совпадает по размеру с test.zip.
- [ ] [HW] По кнопке + приложение без зависания возвращается в hbmenu.
- [x] [host] Имя удалённого файла: `spike_<YYYYMMDD-HHMMSS>.zip`, где время берётся с часов консоли. Каждая загрузка создаёт новый файл, существующие не перезаписываются.
- [x] [host] URL назначения = origin + `/` + basepath + `/` + имя файла; лишние или повторные `/` на стыках убраны.
- [x] [host] Каждый сегмент пути в URL percent-кодируется (пробелы → `%20`); `/` между сегментами не кодируются.
- [x] [host] Запрос PUT собирается с явным Content-Length, равным размеру файла, без `Transfer-Encoding: chunked`, с пустым `Expect:` (заголовок 100-continue не отправляется), HTTP/1.1, с basic auth, проверкой TLS-пира и проверкой имени хоста, таймаутом соединения 15 с и общим таймаутом 120 с.

## Slice 2: Понятные ошибки, повтор и отсутствие зависаний

- [x] [host] HTTP 401 → сообщение «Неверный логин/пароль (401)».
- [x] [host] HTTP 409 → сообщение «Папка на Диске не найдена (409)». MKCOL в фазе 0 не выполняется.
- [x] [host] HTTP 507 → сообщение «Недостаточно места на Диске (507)»; любой другой код не из 2xx → «Ошибка сервера: HTTP <код>».
- [x] [host] Сетевые ошибки curl дают понятные русские сообщения: 6 — «Нет сети / не удалось найти сервер», 7 — «Не удалось подключиться», 28 — «Таймаут», 56 — «Обрыв соединения при обмене данными (56)», 35/60 — «Ошибка TLS / проверки сертификата». Любой другой код → «Ошибка curl <код>: <текст>».
- [x] [host] При кодах curl 6/7/28/56 выполняется 1 повтор после паузы 3 с; при HTTP 4xx, ошибках TLS и успехе повтора нет.
- [ ] [HW] Каждая попытка (1/2) выводит свою строку результата, чтобы повтор не скрывал первую неудачу.
- [x] [host] При ошибке TLS-проверки приложение никогда не повторяет запрос с отключённой проверкой сертификата.
- [ ] [HW] Неверный пароль в config.json → на экране «Неверный логин/пароль (401)», приложение остаётся в меню.
- [ ] [HW] Без сети (авиарежим) → понятное сообщение об ошибке не позже чем через ~2 × 120 с + пауза, приложение не зависает и остаётся в меню.
- [x] [host] Если test.zip нет на SD → сообщение «Файл не найден: sd:/switch/totk-sync/test.zip», сетевой запрос не отправляется.
- [x] [host] Если test.zip пустой или больше 64 МБ → понятное сообщение с размером, сетевой запрос не отправляется.

## Slice 3: Конфигурация и запасной вариант через конфиг JKSV

- [x] [host] Конфиг читается из `sd:/config/totk-sync/config.json` (поля origin, basepath, username, password; keep_backups допускается и игнорируется в фазе 0).
- [x] [host] Если config.json нет, origin/username/password/basepath берутся из `sd:/config/JKSV/webdav.json`, а к basepath добавляется `/The Legend of Zelda Tears of the Kingdom`.
- [ ] [HW] На экране видно, какой файл конфига использован (totk-sync или JKSV).
- [x] [host] Если нет ни одного конфига → сообщение с обоими ожидаемыми путями; кнопка A неактивна.
- [x] [host] Если JSON битый → сообщение «Ошибка разбора <путь>» с позицией или строкой ошибки, если её можно определить.
- [x] [host] Если не хватает обязательного поля или оно пустое → сообщение с именем поля и путём к файлу.
- [x] [host] Если origin не начинается с `https://` → сообщение об ошибке конфигурации (HTTP без TLS не допускается).
- [x] [host] Экранированные символы в строках JSON (`\"`, `\\`, `\/`, `\uXXXX` для кириллицы) декодируются правильно, т.е. результат побайтно совпадает с исходной строкой.

## Slice 4: Диагностический лог

- [x] [host] Каждая попытка дописывает запись в `sd:/switch/totk-sync/log.txt` (каталог создаётся при отсутствии): время, вариант эксперимента, URL, размер файла, HTTP-код, код и текст curl, время в секундах, отправленные байты.
- [x] [host] Заголовки запроса и ответа (из отладочного вывода curl) пишутся в лог, а тело файла не пишется.
- [x] [host] В логе никогда нет пароля: значение заголовка `Authorization` заменяется на `***`, а строка пароля из конфига не встречается в логе ни в каком месте.
- [x] [host] Если запись в лог не удалась, загрузка всё равно выполняется, а на экране один раз показывается предупреждение «Лог недоступен».

## Slice 5: Эксперименты на устройстве без пересборки

Цель — дёшево прогнать на железе матрицу экспериментов из критерия приёмки §6 и воспроизвести поведение JKSV.

- [ ] [HW] На экране меню видны текущие параметры эксперимента и кнопки для их переключения.
- [x] [host] Параметр «Сервер» переключает origin между `https://webdav.yandex.com` и `https://webdav.yandex.ru`; остальная часть URL не меняется.
- [x] [host] Параметр «Expect» переключает между пустым `Expect:` (по умолчанию) и стандартным поведением curl с `Expect: 100-continue`.
- [x] [host] Параметр «Режим тела» переключает между буфером в памяти с явным Content-Length (по умолчанию) и потоковой передачей без известной длины (`Transfer-Encoding: chunked`), как, предположительно, делает JKSV.
- [x] [host] Параметр «Таймауты» переключает между профилем по умолчанию (15 с / 120 с) и длинным профилем (30 с / 600 с).
- [ ] [HW] При запуске приложения параметры всегда сбрасываются на значения §5.4.
- [ ] [HW] Строка результата и запись в логе содержат краткое имя варианта (например, `com|noexpect|cl|t120`), чтобы результаты можно было однозначно перенести в таблицу README.
- [x] [repo] В README есть раздел «Фаза 0 — результаты экспериментов» с пустой таблицей: вариант, HTTP, curl, время, отправлено байт, вывод.
- [ ] [HW] Разработчик заполняет таблицу как минимум для вариантов: по умолчанию; Expect вкл.; chunked; `.ru`; длинный таймаут — и записывает решение: «основной путь» или «fallback §8».

## Нефункциональные требования (на будущее для фаз 1–2)

- Загрузка конфига, сборка URL/запроса, WebDAV-клиент, сопоставление ошибок с сообщениями и лог — отдельные модули с узкими интерфейсами, пригодные для повторного использования в фазах 1–2 без переписывания.
- Чистая логика (разбор конфига, сборка URL и параметров запроса, сопоставление ошибок, маскирование в логе) не зависит от libnx и libcurl на уровне типов, поэтому тестируется на хосте. Тонкий адаптер к libcurl и консольный UI проверяются только на железе.
- Не строить заранее PROPFIND/MKCOL/MOVE/ZIP/JSON-запись — в фазе 0 это не нужно (YAGNI).

## Вне объёма

- Резервное копирование и восстановление сохранений TotK, работа с файловой системой сохранений, ZIP-упаковка (фазы 1–2).
- PROPFIND, MKCOL, MOVE, загрузка `.part`, ротация `keep_backups`.
- Любые запросы DELETE к Яндекс Диску. Тестовые `spike_*.zip` разработчик при необходимости удаляет вручную через веб-интерфейс.
- ПК-лаунчер `pc/totk_sync.py` (§4.1) — отдельная задача после фазы 0.
- Запасной вариант §8 (rclone serve webdav) — только если фаза 0 провалится.
- Dockerfile (Docker на машине отсутствует).
- Отключение проверки TLS в любом виде, включая «отладочный» режим.
- Другие игры, Steam Deck/Linux, другие облака.
- Отмена загрузки посреди передачи.

## Технический контекст

- Репозиторий greenfield: только README.md и LICENSE.
- Стек: devkitPro + libnx, C; HTTP через `switch-curl` из portlibs. **Важно:** пакет switch-curl собран с TLS-бэкендом libnx (`--with-libnx --with-default-ssl-backend=libnx`, без mbedTLS), то есть TLS выполняет системный ssl-сервис Switch. Бэкенд сам вызывает `sslInitialize`; поддерживается TLS только до версии 1.2. CA можно добавить через `CURLOPT_CAINFO` (PEM). Использует ли бэкенд встроенные системные корневые сертификаты, когда `CAINFO` не задан, по исходникам однозначно не видно. Это первое, что нужно проверить на железе. Если проверка падает с ошибкой CA, решение — подложить PEM корневого CA Яндекса (на SD или встроенный в .nro) через `CAINFO`, но **не** отключать проверку. Источник: devkitPro/pacman-packages `switch/curl/PKGBUILD` и `switch-curl.patch`.
- Сеть: приложение должно инициализировать сокеты (`socketInitializeDefault`) и curl (`curl_global_init`) до первой загрузки.
- UI: консоль libnx (`consoleInit`, `printf`, `padGetButtonsDown`).
- JSON: минимальный ручной парсер или однофайловая библиотека, без лишних зависимостей.
- Сборка в Windows: путь проекта содержит пробел и кириллицу, поэтому сборка идёт через `subst`.
- Секреты: пароль не выводится на экран и не пишется в лог; `config.json` в .gitignore.
- Уровень риска: фаза 0 — MODERATE (только чтение с SD и загрузка нового файла); проект в целом — HIGH.

## Решения разработчика (2026-11-03)

1. Переключатели экспериментов на устройстве (Slice 5) — **да**, меню с 4 параметрами: сервер / Expect / режим тела / таймауты.
2. Режим chunked для воспроизведения JKSV — **да**, только как опция эксперимента; по умолчанию явный Content-Length.
3. Повторы — **1 повтор через 3 с** только для curl 6/7/28/56; каждая попытка выводится отдельно.
4. Заголовки запроса и ответа в логе — **да**, Authorization маскируется `***`.
5. Имя удалённого файла — **`spike_<YYYYMMDD-HHMMSS>.zip`**, файлы копятся, удаляются вручную.
6. Лимит размера test.zip — **64 МБ**.
7. Dockerfile — **пропустить** в фазе 0.
8. **2026-11-03, после первого запуска на железе:** шрифт консоли libnx не отображает кириллицу (иероглифы). Решение разработчика — **интерфейс и сообщения на английском** (экран и лог). Русские тексты сообщений в AC ниже читать как их английские эквиваленты (например, «Неверный логин/пароль (401)» → `Wrong login/password (401)`, «УСПЕХ» → `SUCCESS`).
